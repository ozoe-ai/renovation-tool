# 保存エラーとログイン修正

## 確認できた問題

- PCの実画面で、Firestoreへの案件保存が `state.roomCountSettings.totalAreaSqm` の `undefined` 値により拒否されていることを確認しました。総平米数は任意入力ですが、従来のFirestore設定は未入力値のシリアライズを拒否していました。実SDKの書き込み前検証でも同じエラーを再現しました。
- 設定済みGASへの読み取り専用GETはHTTP 200、HTMLの「doGet関数なし」応答でした。POST失敗時のGAS実行ログは取得していないため、元の見積生成エラーまで特定できたとはいえません。
- 従来のGASはテンプレートを毎回コピーしており、書き込み失敗や応答消失後の再試行でファイルが重複し得る構成でした。
- 担当者名を送らない旧アプリと担当者別フォルダ版GASには互換性がありません。今回のアプリ・GASは両方の更新が必要です。

## 修正

- Firestoreに `ignoreUndefinedProperties: true` を設定し、任意項目の未入力値を保存対象から省きます。入力済みの数値や担当者情報は変更しません。
- 外部保存の前に入力内容と案件IDを端末保存します。同じ案件・同じ出力内容には同じ確認IDを割り当てます。
- GASはスクリプトロック、永続的な処理記録、Driveファイルのアプリ用メタデータを用いて途中状態を確認します。作成済みファイルを再利用し、書き込み途中なら同じファイルで再開します。
- コピー要求の結果が不明でファイルも検索できない場合は `COPY_UNCERTAIN` で停止します。重複を避けるため、結果不明の要求を無条件に再送しません。この状態が続く場合は管理者が処理記録とDriveを照合する必要があります。
- 見積ファイルの生成・検証と、案件の共有サーバー保存が成功してから完了表示します。旧GASや不正な成功応答は成功として扱いません。
- ログと画面は段階・定義済みエラーコード・確認IDを使い、認証情報・案件名・見積内容・外部サービスの生の例外は記録しません。
- 上部にメール・パスワード欄を維持し、説明文下の黒い280×60pxボタンから同じフォームを送信します。小さいログイン、新規登録、Googleログインの表示はありません。認証基盤・ログアウト・既存のiPad向け永続化処理は維持します。
- お預かりしたGASのテンプレートID、親フォルダID、計算式、書式、備考、ファイル名規則は維持します。既存ファイルの移動・削除は行いません。修正前のファイルには確認IDがないため、自動的に既存ファイルを選んで上書きすることもしません。

## 反映に必要な作業

1. `outputs/Code.gs` の全文をGASの `Code.gs` に反映します。同じ内容をリポジトリの `scripts/gas/quote-export-template-copy-fixed.gs` にも保存しています。
2. GASエディターで `diagnoseQuoteExport()` を実行し、必要な権限を承認します。この診断は読み取りのみで、見積・フォルダを作成しません。返る `templateIsSpreadsheet`、`canCopyTemplate`、`destinationIsFolder`、`canAddChildren` を確認してください。
3. 新処理はDrive REST APIとUrlFetchを使います。`accessNotConfigured` がログに出た場合はGASに紐づくGoogle CloudプロジェクトのGoogle Drive APIを有効化してください。明示的なOAuthスコープを使っている場合は、既存スコープに加えて `https://www.googleapis.com/auth/drive` と `https://www.googleapis.com/auth/script.external_request` が必要です。
4. GAS実行アカウントにテンプレートの読み取り・コピーと、親フォルダ直下へのファイル／フォルダ作成権限が必要です。Webアプリはサーバーからログイン画面なしで呼び出せる公開設定と実行アカウントにします。`API_SECRET` を使っている場合だけ、アプリの `GAS_API_SECRET` と一致させてください。
5. 既存デプロイを新しいバージョンへ更新し、同じ `/exec` URLを維持します。GETで `protocolVersion: "quote-export-v2"` が返ることを確認します。アプリ側も今回のコードを反映し、端末データを削除せず画面を再読み込みしてください。

旧GASへの新規保存は、重複防止を保証できないためアプリ側の更新確認で停止します。GASとアプリはセットで反映してください。

## 検証範囲

- 自動テスト33件成功。実Firestore SDKでの未入力値のエラー再現と修正確認（コミットなし）、コピー後の応答消失、書き込み失敗、権限拒否、再試行時のファイル再利用、案件保存失敗時の成功表示防止、認証の二重送信防止、編集中の内容を保ったままログイン後に案件一覧へ進む処理を確認しました。
- 実PCブラウザで、上部に入力欄2つ、ログインボタン1つ、黒背景・白文字・280×60px、横方向のはみ出しなしを確認しました。認証後の画面で前述のFirestoreエラーも確認しました。
- 768×1024と320×760のChromeエミュレーションで横方向のはみ出しなしを確認しました。320px幅ではボタンは272×60pxに収まり、入力欄は縦に並びます。iPad Safariの検証ではありません。
- 最終コードで `npx next build --webpack` は成功しました（既存設定によりビルド時の型検証はスキップ）。通常のサンドボックス内では出力ディレクトリへのEPERMが発生したため、承認された通常権限で再実行しました。
- 型チェックは変更前からの `useWizard` 未定義・型重複等で失敗します。
- ご指定に従い、外部GASへのPOST診断と実Driveへの保存テストは実施していません。GAS実行アカウントの実権限・ファイル生成・開けること・再保存の最終確認は反映後に必要です。
- iPad実機のSafari、再読み込み後の認証保持、ログアウト・再ログインの一連の実機操作は未確認です。
